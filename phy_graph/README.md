# phy_graph

ROS-based physical knowledge graph inference module that generates structured scene graphs enriched with semantic and physical information by combining 3D scene understanding with vision-language model (VLM) reasoning.

## Overview

`phy_graph` extracts objects from 3D dynamic scene graphs (DSG) generated by Hydra or BEHAVIOR/OmniGibson simulation, projects them onto RGB camera images, and uses vision-language models to infer physical properties such as friction, weight, and pushability. The system then integrates these physical properties back into the scene graph to create an enhanced knowledge graph.

**Supported DSG Sources:**
- **Hydra**: Real-world SLAM-based dynamic scene graphs
- **BEHAVIOR/OmniGibson**: Simulation with ground truth object positions, bounding boxes, and optional physical properties

### Key Features

- **Dual Projection Modes**: `mesh_vertices` (precise) or `hydra_bbox` (fast)
- **Occlusion Detection**: Optional depth-based occlusion detection
- **VLM-based Physical Inference**: Uses OpenAI GPT-4o-mini to infer physical properties
- **Async Inference Queue**: Non-blocking priority queue for efficient processing
- **Scene Graph Generation**: Generates both full and compact scene graphs
- **Room Classification**: Infers room types based on object composition
- **Fully Configurable**: External YAML configuration for all parameters

## Installation

### Prerequisites

- ROS (recommended: Noetic)
- Python 3.8+
- CMake 3.0+
- catkin build system
- Hydra and hydra_ros packages

### Dependencies

```bash
# ROS dependencies
sudo apt-get install ros-noetic-cv-bridge ros-noetic-tf2-ros ros-noetic-tf2-eigen

# Python dependencies
cd ~/catkin_ws/src/phy_graph
pip install -r requirements.txt
```

### Build

```bash
cd ~/catkin_ws
catkin build phy_graph
source devel/setup.bash
```

### Configuration

Set up OpenAI API credentials:

```bash
export OPENAI_API_KEY="your-api-key-here"
# Optional: For OpenRouter or other compatible services
export OPENAI_API_BASE="https://openrouter.ai/api/v1"
```

## Usage

### Basic Usage

```bash
roslaunch phy_graph inference.launch
```

This launches:
- `phy_graph_server`: Python VLM service
- `phy_graph_node`: C++ inference node
- `graph_generator_node`: Scene graph generator

### Dataset-Specific Launches

```bash
# ADE20K dataset
roslaunch phy_graph inference.launch label_space:=ade20k

# uHuman2 dataset
roslaunch phy_graph dataset.launch
```

### BEHAVIOR Simulation Mode

`phy_graph` supports BEHAVIOR/OmniGibson simulation with ground truth scene graphs. Two modes are available:

#### Real-time Mode (Live Simulation)

1. **Launch phy_graph nodes**:
```bash
roslaunch phy_graph behavior_inference.launch
```

2. **In another terminal, start BEHAVIOR simulation with DSG publishing**:
```bash
cd ~/catkin_ws/src/phy_plan/env
conda activate phyplan  # Required for spark_dsg
python behavior_ros.py --scene office_vendor_machine --publish_dsg true
```

The `behavior_ros.py` script will:
- Run OmniGibson simulation
- Publish RGB/Depth images and camera TF
- Publish DSG messages with ground truth object positions, bounding boxes, and categories
- Optionally include ground truth physical properties (mass, weight_level, pushable)

**Key features:**
- DSG is built from OmniGibson scene objects in real-time
- Object bounding boxes are extracted directly from `obj.aabb_extent` (no hardcoded dimensions)
- Room information is automatically extracted from object-room relationships
- Compatible with existing `phy_graph` C++ node for image processing and VLM inference

#### Offline Mode (Rosbag Playback)

For processing recorded rosbag data:

1. **Launch phy_graph with JSON-based DSG**:
```bash
roslaunch phy_graph behavior_offline.launch \
    json_path:=/path/to/scene.json \
    dsg_rate:=2.0
```

2. **In another terminal, play the rosbag**:
```bash
rosbag play recording.bag
```

**Configuration:**
- `json_path`: Path to BEHAVIOR scene JSON file (e.g., `office_vendor_machine_0.json`)
- `dsg_rate`: Publishing frequency for static DSG (default: 2.0 Hz)
- `categories`: Optional comma-separated list to filter specific object categories

**Label Space Configuration:**

Edit `config/label_spaces/behavior.yaml` to filter objects for physical inference:

```yaml
# Included categories (objects relevant for robot manipulation)
included_categories:
  - "chair"
  - "swivel_chair"
  - "table"
  - "conference_table"
  - "coffee_cup"
  # ... (lamp and plant are excluded by default)

# Excluded patterns (scene structure and decorative objects)
excluded_patterns:
  - "wall*"
  - "floor*"
  - "lamp*"
  - "plant*"
```

**Note:** `phy_graph` uses category names (not semantic label IDs) for filtering. Semantic labels in DSG are set to 0 by default, as they are not used by `phy_graph`.

### Custom Topics

```bash
roslaunch phy_graph inference.launch \
    rgb_topic:=/your_camera/rgb/image_raw \
    camera_info_topic:=/your_camera/camera_info
```

## Configuration

All parameters are configured in `config/inference_config.yaml`:

```yaml
# Image processing
image:
  projection_mode: "hydra_bbox"  # "mesh_vertices" or "hydra_bbox"
  score_threshold: 60.0
  high_quality_threshold: 70.0

# Keyframe database
keyframe:
  max_memory_frames: 3000
  time_window: 8.0
  frame_skip: 5

# Inference queue
inference:
  num_workers: 1
  max_queue_size: 100
  wait_timeout: 5.0

# VLM service
vlm:
  model_name: "openai/gpt-4o-mini"
  max_retries: 3
  dry_run: false  # Set true to skip API calls

# Object maturity
object_maturity:
  enable: true
  min_age_seconds: 1.0

# Occlusion detection
occlusion:
  enable: true
  depth_threshold: 0.1

# Debug
debug:
  save_images: true
  verbose: false
```

### Label Filtering

Edit `config/label_spaces/ade20k.yaml`:

```yaml
# Include list (whitelist)
included_labels:
  - 5        # Semantic label ID
  - "chair"  # Name pattern (case-insensitive)
  - "couch*" # Wildcard pattern

# Exclude list (blacklist)
excluded_labels:
  - 1
  - "wall*"
```

## Output

### Object Physical Properties

Each object generates: `output/<timestamp>/object_<node_id>_<label>.json`

```json
{
  "object_id": "O(1)",
  "label": "couch",
  "description": "A blocky, polygonal black couch.",
  "friction_level": 1,
  "pushable": true,
  "weight_level": 1,
  "estimated_weight_kg": "15-25",
  "inference_confidence": 78
}
```

### Scene Graphs

Two formats are generated in `output/scene_graphs/`:

- **`scene_graph_latest.json`**: Full scene graph with all details
- **`scene_graph_compact_latest.json`**: Compact format for LLM planning

```json
{
  "schema_version": 1,
  "physical_source_dir": "2025-09-03_14-04-19",
  "scene_graph": {
    "timestamp": "2025-09-03_14:04:19",
    "rooms": [
      {
        "room_id": "R(0)",
        "category": "LivingRoom",
        "object_ids": ["O(1)", "O(2)"]
      }
    ],
    "objects": [
      {
        "node_id": "O(1)",
        "category": "couch",
        "physical_properties": {
          "friction_level": 1,
          "pushable": true,
          "weight_level": 1,
          "estimated_weight_kg": "15-25"
        }
      }
    ]
  }
}
```

## Troubleshooting

### No Objects Processed
- Check DSG is publishing: `rostopic echo /hydra_ros_node/backend/dsg`
- Verify label filtering matches your dataset
- Check object maturity settings

### VLM Service Fails
- Verify `OPENAI_API_KEY` is set: `echo $OPENAI_API_KEY`
- Check service: `rosservice list | grep get_physical_properties`

### No Images Extracted
- Verify RGB topic: `rostopic hz <rgb_topic>`
- Check camera_info is received
- Ensure TF tree includes world→camera transform
- Verify projection mode matches your setup

### Scene Graph Not Updating
- Verify `graph_generator_node` is running
- Check output directory: `ls output/<timestamp>/object_*.json`
- Review DSG update frequency

### BEHAVIOR Mode Issues

**DSG not publishing in real-time mode:**
- Verify `behavior_ros.py` is running with `--publish_dsg true`
- Check conda environment: `conda activate phyplan` (required for `spark_dsg`)
- Verify DSG topic: `rostopic echo /hydra_ros_node/backend/dsg`
- Check for import errors: `python -c "import spark_dsg"`

**No objects in offline mode:**
- Verify JSON file path is correct
- Check JSON contains `objects_info` and `state.registry.object_registry`
- Review category filtering in `config/label_spaces/behavior.yaml`
- Check DSG publisher is running: `rosnode list | grep behavior_dsg`

**Objects missing from DSG:**
- Review `EXCLUDED_CATEGORIES` in `phy_plan/env/util/dsg_utils.py`
- Check label space configuration excludes desired objects
- Verify OmniGibson scene has objects with valid categories

## Architecture

The system consists of three main components:

1. **Physical Inference Node** (`phy_graph_node`): Extracts object images from DSG and RGB streams, calls VLM service
2. **VLM Service** (`phy_graph_server`): Python ROS service that interfaces with OpenAI API
3. **Graph Generator Node** (`graph_generator_node`): Integrates physical properties with DSG to generate enhanced scene graphs

```
DSG Source (Hydra or BEHAVIOR) → phy_graph_node → KeyframeDatabase
                ↓
    3D Projection → Image Scoring (+ Occlusion)
                ↓
    Async Inference Queue → VLM Service
                ↓
    Physical Properties (JSON)
                ↓ 
    graph_generator_node → Enhanced Scene Graph
```

**BEHAVIOR Mode Data Flow:**
```
OmniGibson Scene → behavior_ros.py → DsgPublisher (dsg_utils.py)
                ↓
    spark_dsg.DynamicSceneGraph → ROS DsgUpdate message
                ↓
    phy_graph_node (same as Hydra mode)
```

**Key Differences:**
- **Real-time**: DSG built from `og_scene.objects` with direct access to `aabb_extent`, `aabb_center`, `mass`
- **Offline**: DSG built from JSON file using `BehaviorDsgBuilder` (dsg_builder.py)
- Both modes use the same `phy_graph_node` C++ code for image processing and VLM inference
