# phy_graph

`phy_graph` is a ROS-based physical knowledge graph inference module that generates structured scene graphs enriched with semantic and physical information by combining 3D scene understanding with vision-language model (VLM) reasoning.

---

## 🎯 Overview

`phy_graph` extracts objects from 3D dynamic scene graphs (DSG) generated by Hydra, projects them onto RGB camera images, and uses vision-language models to infer physical properties such as friction, weight, and pushability. The system then integrates these physical properties back into the scene graph to create an enhanced knowledge graph.

### Key Features

- **3D-to-2D Projection**: Projects 3D mesh vertices onto RGB images for accurate object extraction
- **Intelligent Image Selection**: Scores and selects the best view of each object using visibility, coverage, and position metrics
- **VLM-based Physical Inference**: Uses OpenAI GPT-4o-mini to infer physical properties from object images
- **Hybrid Keyframe Storage**: Efficiently manages image data with hot (memory) and cold (disk) storage
- **Scene Graph Integration**: Combines physical properties with DSG structure to generate enhanced scene graphs
- **Room Classification**: Infers room types based on object composition using rule-based reasoning

---

## 🏗️ System Architecture

The system consists of three main components:

### 1. Physical Inference Node (`phy_graph_node`)

**Purpose**: Extracts object images from DSG and RGB streams, then calls VLM service to infer physical properties.

**Workflow**:
1. Subscribes to Hydra DSG updates and mesh messages
2. Maintains a keyframe database of RGB images with camera poses
3. When a new object is detected in DSG:
   - Projects the object's 3D mesh onto candidate RGB images
   - Scores each candidate based on visibility, coverage, and position
   - Selects the best image and extracts the object region
   - Calls the VLM service to infer physical properties
   - Saves results as JSON files

**Key Components**:
- `PhysicalInferenceNode`: Main node class
- `KeyframeDatabase`: Hybrid storage (memory + disk) for RGB keyframes
- Image projection and scoring algorithms

### 2. VLM Service (`phy_graph_server`)

**Purpose**: Python ROS service that interfaces with OpenAI API for physical property inference.

**Workflow**:
1. Receives object image and label via ROS service
2. Encodes image to base64
3. Sends request to OpenAI/OpenRouter API with structured prompt
4. Parses JSON response and returns physical properties

**Physical Properties**:
- `description`: Textual description of the object
- `friction_level`: Integer 0-2 (0=low, 1=medium, 2=high)
- `pushable`: Boolean (whether a mobile robot can push it)
- `weight_level`: Integer 0-2 (0=light, 1=medium, 2=heavy)

### 3. Graph Generator Node (`graph_generator_node`)

**Purpose**: Integrates physical properties with DSG to generate enhanced scene graphs.

**Workflow**:
1. Subscribes to DSG updates
2. Loads physical property JSON files from output directory
3. Extracts objects and rooms from DSG
4. Matches physical properties to objects
5. Infers room categories based on object composition
6. Generates and saves enhanced scene graph as JSON

**Output**: `scene_graph_latest.json` containing:
- Room nodes with inferred categories
- Object nodes with physical properties
- Spatial relationships and hierarchies

### Prerequisites

- **ROS** (recommended: Noetic)
- **Python 3.8+**
- **CMake 3.0+**
- **catkin** build system

```bash
sudo apt-get install ros-noetic-cv-bridge ros-noetic-tf2-ros ros-noetic-tf2-eigen
```

## 🔬 Code Principles

### Image Extraction Pipeline

1. **Keyframe Selection** (`KeyframeDatabase`):
   - Subscribes to RGB images at 30Hz
   - Downsamples to ~3Hz (every 10th frame)
   - Stores keyframes based on motion criteria:
     - Minimum translation: 0.2m
     - Minimum rotation: 0.1 rad
     - Minimum time interval: 0.2s
   - Maintains up to 3000 frames in memory, offloads older frames to disk

2. **3D-to-2D Projection** (`projectObjectToImage`):
   - Transforms object mesh vertices from world to camera frame
   - Projects using pinhole camera model:
     ```
     u = fx * X/Z + cx
     v = fy * Y/Z + cy
     ```
   - Filters vertices behind camera (Z ≤ 0.1m)
   - Computes 2D bounding box from projected points

3. **Image Scoring** (`scoreCandidateImages`):
   - **Visibility Score (40 points)**: Ratio of visible vertices
     - >80% visible: 40 points
     - >50% visible: 30 points
     - >30% visible: 20 points
     - Otherwise: 10 points
   - **Coverage Score (30 points)**: Object area / image area
     - 10-40% coverage: 30 points (ideal)
     - 5-60% coverage: 20 points
     - >1% coverage: 10 points
   - **Position Score (15 points)**: Distance from image center
   - **Edge Score (15 points)**: Bonus if object is not near edges
   - **Total**: 0-100 points, threshold ≥60 for acceptance

4. **Best Image Selection** (`extractBestObjectImage`):
   - Searches within ±10 seconds of object creation time
   - Scores all candidate images
   - Selects highest-scoring image
   - Expands bounding box by 30% padding
   - Extracts and returns cropped image

### Deferred Inference Logic

To optimize inference quality:
- **High Quality (Score ≥80)**: Immediate inference
- **Medium Quality (40-80) & New Object (<5s)**: Wait for better view
- **Low Quality or Old Object**: Force inference (best effort)

### Physical Property Inference

The VLM prompt requests:
```json
{
  "description": "Brief textual description",
  "friction_level": 0-2,
  "pushable": 0 or 1,
  "weight_level": 0-2
}
```

The system handles:
- JSON extraction from markdown code blocks
- Retry logic (up to 3 attempts)
- Error handling and validation

### Scene Graph Generation

1. **Object Extraction** (`extractObjectsFromDSG`):
   - Iterates through DSG OBJECTS layer
   - Extracts position, bounding box, and semantic label
   - Matches with physical properties from JSON files

2. **Room Extraction** (`extractRoomsFromDSG`):
   - Iterates through DSG ROOMS layer
   - Collects child object IDs

3. **Room Classification** (`inferRoomCategory`):
   - Uses rule-based scoring system
   - Room types: Bedroom, Bathroom, Kitchen, LivingRoom, Office, DiningRoom
   - Stability tracking: Only classifies after 1.5s of stability
   - Scores objects by importance (e.g., bed=10, nightstand=3)

4. **Graph Assembly** (`buildSceneGraph`):
   - Combines rooms and objects
   - Adds timestamps
   - Saves as JSON

Each object generates a JSON file: `object_<node_id>_<label>.json`

```json

  "label": "couch",
  "description": "A blocky, polygonal black couch.",
  "friction_level": 1,
  "pushable": true,
  "weight_level": 1,
  "processing_time_ms": 2980
```

```json
  "objects": [
    {
      "node_id": "O(1)",
      "category": "couch",

      "bbox_max": [1.6, 0.8, 0.5],

        "friction_level": 1,
        "pushable": true,
        "weight_level": 1,
        "description": "A blocky, polygonal black couch."
      }
    }
  ]
}
```

### Label Whitelist

Edit `config/ade20k.yaml` or `config/uhuman2.yaml` to specify which object labels to process:

```yaml
object_labels:
  - 5   # Semantic label ID
  - 6
  - 7
```

### Keyframe Database Parameters

Modify in `nodeSub.cpp`:
- `max_memory_frames`: 3000 (frames in RAM)
- `min_translation`: 0.2m
- `min_rotation`: 0.1 rad
- `min_time_interval`: 0.2s

### VLM Model Selection

Edit `scripts/module.py`:
```python
model_name="openai/gpt-4o-mini"  # Change to "gpt-4o" for better quality
```

### Image Quality Thresholds

Modify in `imageProcessor.cpp`:
- `HIGH_QUALITY_THRESHOLD`: 80.0
- `WAIT_TIMEOUT_SECONDS`: 5.0
- Minimum score for acceptance: 60.0

## 🐛 Troubleshooting

### No Objects Processed

- Check DSG is publishing: `rostopic echo /hydra_ros_node/backend/dsg`
- Verify label whitelist matches your dataset
- Check ROS logs for filtering messages

### VLM Service Fails

- Verify `OPENAI_API_KEY` is set: `echo $OPENAI_API_KEY`
- Check service is running: `rosservice list | grep get_physical_properties`
- Review Python logs for API errors

### No Images Extracted

- Verify RGB topic is publishing: `rostopic hz <rgb_topic>`
- Check camera_info is received (required for projection)
- Ensure TF tree includes world→camera transform
- Check keyframe database size: Look for "KeyframeDatabase" logs

### Scene Graph Not Updating

- Verify `graph_generator_node` is running
- Check output directory has object JSON files
- Review DSG update frequency (should be >0.5Hz)

## 📚 API Reference

### ROS Topics

**Subscribed**:
- `input_mesh` (kimera_pgmo_msgs/KimeraPgmoMesh): 3D mesh data
- `rgb_image` (sensor_msgs/Image): RGB camera images
- `camera_info` (sensor_msgs/CameraInfo): Camera intrinsics

**Published**: None (results saved to filesystem)

### ROS Services

**Provided**:
- `get_physical_properties` (phy_graph/GetProperties): VLM inference service

**Request**:
```
string label
sensor_msgs/Image image
```

**Response**:
```
string description
int8 friction_level
bool pushable
int8 weight_level
```

### ROS Parameters

- `~label_space` (string): Label space name (e.g., "ade20k", "uhuman2")
- `~object_labels` (array[int]): Whitelist of semantic label IDs
- `~debug_save_images` (bool): Save extracted images for debugging

## 🎓 Key Concepts

### Dynamic Scene Graph (DSG)

A hierarchical graph structure from Hydra containing:
- **Layers**: OBJECTS, ROOMS, PLACES, etc.
- **Nodes**: Objects with attributes (position, bounding box, semantic label)
- **Relationships**: Parent-child relationships (e.g., room contains objects)

### Keyframe Database

Hybrid storage system:
- **Hot Storage**: Recent 3000 frames in RAM (compressed JPEG)
- **Cold Storage**: Older frames on disk
- **Automatic Offloading**: FIFO policy when memory limit reached

### Image Quality Scoring

Multi-factor scoring system:
- **Visibility**: How much of the object is visible
- **Coverage**: Object size relative to image
- **Position**: Distance from image center
- **Edge Distance**: Whether object is near image boundaries
